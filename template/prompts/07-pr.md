# 07 · 提交与 PR

## 使用场景

按 Git 规范提交代码、生成 PR 信息。

## 开始工作 Prompt（从 issue 启动一条分支）

```
请按这个 GitHub issue 工作：

Issue: #[N] [标题]
[粘贴 issue 内容]

工作流程：
1. 先复述目标、验收标准和不要动的范围
2. 确认对应 spec 和任务账本存在（没有就先停下，走 /spec → /tasks）
3. 创建分支：[type]/[issue号]-[简短描述]
4. 按账本逐任务做，小步 commit，每个 commit 只做一件事
5. commit message 格式：<type>(<scope>): <描述>\n\nRefs #[N]
6. 每次提交前门禁会自动跑；失败只根据失败信息做最小修复

不要自动合并，不要扩大 scope。
```

## PR 创建 Prompt

```
代码已完成，门禁全绿，账本全部 ✅。请生成 PR 信息。

格式：
---
Title: <type>(<scope>): <简短描述>

Body:
Closes #[N]

## 做了什么
- （1-3 条，每条一句话）

## 行为变化
- 无（纯重构）
- 或列出具体变化

## 测试
- [x] 特征测试全绿
- [x] 新增/更新测试覆盖验收标准 AC-1 … AC-n
- [x] 质量门禁通过
- [x] 任务账本已更新（spec/planned/<spec>.tasks.md）
- [ ] spec 状态已更新（等合并后由人移动）

## Checklist
- [ ] 一个 PR 只做一件事
- [ ] 没有混入重构/bug fix/新功能
- [ ] commit history 干净可读
- [ ] 不改 spec 没提到的代码
---
```

## Commit 规范速查

| type | 含义 | 示例 |
|---|---|---|
| feat | 新功能 | feat(shipping): add international rate calculation |
| fix | 修 bug | fix(coupon): correct threshold comparison operator |
| refactor | 重构（不改行为） | refactor(checkout): extract _apply_vip from checkout |
| test | 只加/改测试 | test(checkout): add characterization tests for VIP stacking |
| docs | 只改文档 | docs(spec): add shipping calc spec |
| chore | 构建/工具/配置 | chore(ci): add ruff to GitHub workflow |

## 1. 目标

用一句话说清楚这个 spec 要解决什么问题。

## 2. 背景

为什么要做。现状是什么，痛点在哪。

## 3. 设计方案

### 3.1 边界（什么锁死）

- 入口/API 签名：（不能变的部分）
- 返回结构：（字段、精度）
- 兼容约束：（下游依赖什么）

### 3.2 实现空间（什么留给 AI 发挥）

- 内部实现细节
- 私有函数命名和拆分方式
- 性能优化手段（在不改变行为的前提下）

### 3.3 不做什么（显式排除）

- 不改 XXX
- 不处理 YYY 场景（留给后续 spec）

## 4. 验收标准

每条必须可测试。AI 写完后，人按这些条目逐条验收。编号从 AC-1 起，任务账本和测试都引用这个编号。

- [ ] AC-1：条件A下，返回/行为是X
- [ ] AC-2：条件B下，返回/行为是Y
- [ ] AC-3：性能：不超过 Z ms
- [ ] AC-4：错误处理：异常情况返回/抛出什么

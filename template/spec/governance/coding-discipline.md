# Governance: 编码纪律

> 状态：`governance`（长期生效）
> 创建日期：YYYY-MM-DD

---

## 适用范围

本规则适用于所有 AI agent 和人类开发者在本项目中的代码产出。

## 规则

### R1: 重构 ≠ 修 bug

重构的定义是**改变结构，不改变行为**。发现 bug 时：
- 先把 bug 的当前行为锁进特征测试
- 重构 PR 里不修 bug
- bug 单独开 issue、单独 PR

### R2: 测试是安全网，不是形式

- 特征测试锁**现状**，不锁理想
- 回归测试锁**验收标准**
- 测试红 = 行为变了 = 必须停下来判断

### R3: 一个 PR 一件事

- 混合 PR（重构+新功能+修 bug）一律打回
- 原因：出问题时不知道该 revert 哪部分

### R4: Public API 是契约

以下变更必须先写 spec、人审批后才能做：
- 函数签名变更
- 返回结构变更
- 异常类型变更
- import 路径变更
- 配置项格式变更

### R5: 先理解，后动手

对任何不熟悉的代码：
1. 先用架构梳理 prompt 让 AI 只读
2. 确认理解后再写 spec
3. 写完 spec 人审后再写代码

### R6: 业务语义由人裁决

- 领域术语（哪两个概念是同一件事、哪个字段是主键、哪条流程是主路径）AI 只能提出假设，不能自行拍板
- spec 第 9 节"自检记录"里的"领域假设"必须由业务裁决人确认后才能实现

### R7: 账本是唯一真相

- 任务进度只记在 `*.tasks.md`，不记在对话里
- 会话结束前必须把账本状态更新到最新；下一个会话从账本开始

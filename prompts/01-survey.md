# 01 · 架构梳理（AI 只读不改）

## 使用场景

面对一段不熟悉的遗留代码，让 AI 先读懂结构，再决定下一步。这是碰遗留代码的第一步，没有例外。

## Prompt 模板

```
请只读以下代码，不要修改任何文件。

输入：[文件路径或目录路径]

请输出以下五项内容：

## 1. Public API / 入口清单
- 列出所有对外暴露的函数、类、接口、路由
- 标注哪些是主入口（最常被调用的）

## 2. 职责板块
- 每个函数/类负责什么业务逻辑
- 如果有多套实现（如 calc_v1, calc_v2），分别说明，并指出哪套是主路径

## 3. 状态地图
- 持久化存储：数据库/文件/缓存 读写在哪
- 全局变量/模块级变量：谁在读写
- 配置：从哪里加载、运行时是否可变

## 4. 依赖关系
- import 关系（特别标出近循环依赖）
- 隐式依赖（通过全局变量、事件、import 副作用）
- 下游调用面（谁在用这段代码）

## 5. 可疑行为清单
- 看着像 bug 但不确定的行为
- 多套实现之间的不一致
- 可能的竞态条件或状态泄漏
- 每条说明"为什么可疑"和"为什么不能顺手改"

要求：
- 先描述现状，不要给重构方案
- 不要顺手修 bug
- 如果代码太长无法一次读完，列出你没覆盖的部分
- 输出写到 docs/survey/<模块名>.md（如果目录不存在就建），方便后续 /lock 引用
```

## 人审要点

- [ ] public API 有没有遗漏（特别是老入口、兼容入口）
- [ ] 隐式状态有没有漏掉（全局变量、import 副作用）
- [ ] 下游调用面有没有少列
- [ ] 可疑行为是否和你了解的实际情况一致

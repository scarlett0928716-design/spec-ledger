# 07 · 安全重构（小步红绿）

## 使用场景

特征测试全绿后，开始小步重构。

## 前置条件

- 特征测试已全部通过（tests/characterization/）
- 重构目标已在 spec 中明确，任务账本已拆好
- 人已审批重构范围

## Prompt 模板

```
特征测试已全绿。请做一次小步安全重构。

目标：[具体说明本步要做什么，如"将 checkout() 中的运费计算逻辑抽成独立函数 _calc_shipping()"]
对应账本任务：[T-n]

约束：
- 保留 public API / 入口 / 返回结构不变
- 一次只重构一个职责块
- 保留旧入口，内部委托到新函数（绞杀者模式）
- 每完成一步运行全部特征测试
- 测试失败时：
  - 先解释哪条行为发生了变化
  - 判断是测试问题还是行为真的变了
  - 给最小修复方案
- 禁止：
  - 顺手修 bug
  - 新增功能
  - 改变 public API 签名
  - 移动文件/目录

请先给本步计划（改什么、不改什么、预期结果），等我确认后再改代码。
```

## 分步执行模板（大重构拆多步）

```
本次重构分 N 步完成，每步一个 commit，对应账本 T1…Tn：

Step 1: [描述] → 预期：测试全绿，行为不变
Step 2: [描述] → 预期：测试全绿，行为不变
...

请从 Step 1 开始。完成后报告测试结果并更新账本，我确认后再进入下一步。
```

## 红灯处理

```
测试 [测试名] 失败了。

请分析：
1. 哪条行为发生了变化？
2. 是重构引入的还是测试本身的问题？
3. 如果是重构引入的：给出最小修复（恢复原行为），不要扩大修改范围
4. 如果是测试问题：说明原因，但不要自行修改测试，等我确认

不要继续下一步重构。先解决这个红灯。账本对应任务改为 ⏸ 并记录。
```

## 人审要点

- [ ] diff 是否只做了一件事？
- [ ] public API 签名是否完全不变？
- [ ] 是否有"顺手"的额外修改？
- [ ] commit message 是否清楚说明了本步做了什么？
- [ ] 特征测试是否仍然全绿？

# 06 · 新功能开发（Spec → Tasks → Test → Code）

## 使用场景

Spec 已审批、任务账本已拆好，按 TDD 红绿循环实现。

## 前置条件

- `spec/planned/<spec>.md` 已人审
- `spec/planned/<spec>.tasks.md` 已存在（没有就先 /tasks）

## Prompt 模板

```
请按照 spec/planned/<id>-<name>.md 和它的任务账本 <id>-<name>.tasks.md 实现功能。

工作顺序（必须按此顺序）：
0. 先读 AGENTS.md、CONTEXT.md、spec 文件、任务账本
1. 列出本功能的测试接缝（spec 第 6 节"测试计划"里的层级），等我确认；未确认的接缝不写测试
2. 从账本里第一个 ⬜ 且依赖已满足的任务开始；开始前把状态改为 🔴
3. 测试任务：按 AC 在确认的接缝上写测试（用 CONTEXT.md 的术语命名）→ 运行 → 确认红
4. 实现任务：写最小实现让测试绿，不破坏前面的绿 → 状态改 🟢
5. 跑质量门禁（bash scripts/gate.sh）全绿后提交 → 状态改 ✅ 并填 commit 哈希
6. 回到第 2 步，直到账本全部 ✅

约束：
- 严格遵守 spec 中"边界（什么锁死）"的定义
- 只在 spec 中"实现空间"允许的范围内发挥
- 不做 spec "不做什么"节列出的事情
- 不改 spec 没提到的代码
- 遵守 R8：不 mock 内部、期望值来自 spec 或独立算例、一个接缝一个测试一个最小实现，不先把测试全写完
- 遇到 spec 没覆盖的情况或词汇表没有的术语：停下，在账本"阻塞与裁决记录"里写明，不要自己决定

每完成一个任务报告一次：
- ✅ 已完成的任务 / AC
- 🔴 当前正在处理的
- ⬜ 还没开始的
- ⏸ 阻塞的（及原因）

全部完成后报告：
- 哪些验收标准已通过
- 是否有验收标准无法满足（及原因）
- 账本是否已更新到最新
```

## 人审要点

- [ ] 测试是否覆盖了 spec 中的所有验收标准？
- [ ] 实现是否超出了 spec 定义的边界？
- [ ] 是否做了 spec "不做什么"里列出的事？
- [ ] 账本状态和 git log 是否对得上？
- [ ] commit 是否只包含本功能相关代码？
